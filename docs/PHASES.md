### Phase 1 implementation decisions

- **Schema file location:** the spec's repo tree says `src/content/config.ts`; current Astro (v7) requires `src/content.config.ts`. Schemas live there; content folders match the spec.
- **Enum values are slugs** (e.g. `battery-charging`, `rebuild-service`, `hand-tool`) with display labels in `src/lib/enums.ts`. Source `type` keeps `OEM` / `OEM-equivalent` as written in the spec example.
- **Unknown values are the literal `TODO`.** Allowed for URLs, prices, `last_verified` and `time_minutes`; anything else unknown is simply omitted.
- **Strict schemas:** unknown or misspelled fields fail the build. This also enforces "`used_in` is never typed" for tools.
- **Cross-reference checks fail the build.** Astro only logs broken `reference()` targets, so `src/lib/validate.ts` (run via the prerendered `/content-check.json`) throws. `npm run test:validation` proves five kinds of bad files are rejected, and runs in CI.
- **Additions beyond the spec's field tables** (flag if unwanted):
  - Guides have a required `confidence` field (confirmed / community-reported / theory), because the Governance section says trust levels show on every guide.
  - Vendors have `references` (links backing vendor facts), and `ships_to_us` / `us_warehouse` are `yes / no / some-items / unknown`, not booleans, so we never have to guess.
  - Troubleshooting `checks` are `{ step, pass, fail }`; `fix` is a list of `{ guide?, part?, note? }`.
  - Tool `buy_links[].vendor` is a free-text store name, not a vendor id, since the vendors collection is for parts sellers.
- **`noindex` on every page** until the public launch (Phase 6).

### Phase 4 implementation decisions

- **One definition for both kinds of form.** `src/lib/contribution.ts` defines the four types (broken link, suggest a part or vendor, share a fix, correct a spec), their fields, per-type labels, required rules, options and repo labels. `scripts/sync-issue-forms.ts` generates `.github/ISSUE_TEMPLATE/*.yml`, `config.yml` and `src/data/part-options.ts` from it and from `src/content/parts`. `npm run forms:check` (in CI) fails when they're stale; run `npm run forms:sync` after adding, renaming or removing a part. The web form and the function import the same module.
- **Part dropdown text is `Name · id`** so issues stay unambiguous if a part is renamed. Two extra options: "Not about one part" and "A part that isn't listed".
- **Issue forms can only set fixed labels,** so `.github/workflows/issue-labels.yml` adds `new-part` / `new-vendor` (from the suggestion answer) and `needs-source` (empty "Source or photo"; not for broken links). The function applies the same rules itself (`labelsFor()`), plus `web-form`. `community-reported` is applied by the editor when publishing without a source. `npm run labels:sync` created all eight labels.
- **"Report a problem" goes to the web form, not GitHub.** It works with or without an account and is prefilled (`type`, `part`, `system`, `page`; "report broken link" adds `vendor` and `url`). The form links to the matching GitHub issue form, prefilled the same way, when GitHub contributions are open. Defaults: part pages → Correct a spec; guides and troubleshooting → Share a fix. "Share a fix" (part sidebar), "help verify it" (new, next to a guide's "not yet" verified badge), Specs, Tools and Community links all open the form prefilled.
- **"Edit this page" targets:** content pages open their source file; non-content pages open their `.astro` file, Specs opens `src/data/specs.ts`, and 404 now has a target too. Before launch the link reads "edit this page (opens at launch)" and goes to `/contribute#edit`.
- **The function** is `api/contribute.ts` (Vercel Node function, web-standard `POST(request)`), with server code in `api/_lib/server.ts`. The rest of the site stays static (no Astro adapter). It checks the same origin, caps the body at 32 KB, drops honeypot hits silently, validates, applies a per-IP limit (5 per 10 minutes, per instance), verifies Turnstile, checks a global cap (`WEBFORM_HOURLY_CAP`, default 20 web-form issues an hour, counted on GitHub), then files the issue with an installation token scoped to this repo's issues. User text has @mentions and #refs defanged. JSON responses go to the enhanced form; plain POSTs get a 303 redirect to `/contribute/thanks` or back to the form with an error code. Failures never echo details; causes go to Vercel's runtime logs.
- **Vercel compiles `api/` as Node ESM (nodenext),** so relative imports in the function's chain (`api/`, `src/lib/contribution.ts`, `src/site.config.ts`, `src/lib/enums.ts`, `src/data/part-options.ts`) need explicit `.js` specifiers. Without them the first preview returned 500. Vite and tsx resolve `.js` to `.ts`.
- **Without JavaScript:** the form still posts, but Turnstile needs JS, so a `<noscript>` notice explains that (and links the GitHub forms once open). Everything else is progressive: prefill, per-type fields, inline errors and the in-page success state need JS; the plain POST and result page work without it.
- **Photo upload on the web form is a link, not a file.** Issue forms accept drag-and-drop photos. The web form's "Source or photo" field takes a link instead. Hosting uploads would need storage (e.g. Vercel Blob), moderation, and EXIF/location stripping. Deferred; revisit if owners ask for it.
- **The web form adds a disclosure checkbox** ("I sell this, or I work for this store or vendor") on broken-link and suggest forms, enforcing the Governance vendor-disclosure rule, and a required CC BY-SA 4.0 agreement on all four.
- **Local testing:** `npm run build && npm run serve:local -- --stub-github` serves `dist/` plus the function with test Turnstile keys and a fake GitHub. `npm run test:contribution` (in CI) covers validation, labels, formatting, the JWT, and the function's success, Turnstile failure, bad input, honeypot, origin, cap, per-IP and missing-credentials paths, with the network stubbed.
- **Template tweaks (no restyle):** PageMeta's actions span the full width when a page has no sources, so they sit side by side. The form reuses the parts-filter select pattern, the shared `.btn` and the row inset/hover for its type choices. The Turnstile widget is a cross-origin iframe and can't take `.btn`; it uses `data-size="flexible"` to fit 375px.
- **Two Vercel projects** were briefly linked to the repo on Nov 12 (`metacycle-resource` and a duplicate `metacycle-resource-1cxp`). Only `metacycle-resource` should remain; it holds the env vars and serves production. If PR checks ever show a second Vercel context again, delete the extra project.
- **Env var names:** Vercel warns about `PUBLIC_`-prefixed variables, so the build-time flags are `GITHUB_CONTRIBUTIONS` (Preview only, `true`) and `TURNSTILE_SITE_KEY`. Both are read only in Astro frontmatter at build time.
- **GitHub issue forms don't prefill dropdowns from URL query parameters** (checked with Derek's account: text fields fill, dropdowns stay "None", even for an exact plain-text match). The web form's "use the GitHub form" link therefore also puts the part in the issue title, and the page field carries the part's path.
- **Tooling:** in this workspace `gh` works only for repo-scoped REST calls (GraphQL and device login are blocked by the proxy), so open PRs with `gh api repos/…/pulls`. The Vercel MCP can read deployments and logs and create share links, but gets 403 on environment variables; ask Derek to set them.

### Phase 5 implementation decisions

- **One staleness rule.** `src/lib/staleness.ts` (plain TS, reads `site.staleAfterDays`) has `isStale`, `checkReasons` (dead, out-of-stock, never verified, stale, unverified, no link, no price) and `summarize`. The badge (`format.ts`), Help Wanted, the checker report and `verify-list` all use it. `verify-list` moved to TypeScript (`tsx scripts/verify-list.ts`) to import it; its output didn't change. Shared YAML loading for scripts is in `scripts/lib/content-files.ts`.
- **Link outcomes** (`src/lib/link-rules.ts`, classification in `scripts/lib/link-classify.ts`): live · dead · likely out of stock · redirects to the home page · couldn't reach · needs a human. Only dead, out of stock, moved and couldn't reach keep the rolling issue open. "Needs a human" doesn't, or the issue could never close (34 of 72 URLs are on blocked hosts or behind bot walls). Those links are listed on Help Wanted instead.
- **Stock detection uses structured data only** (schema.org `availability` in JSON-LD or microdata, og/product `availability` meta). A page counts as out of stock only when no variant is in stock. Page text like "sold out" is ignored because it shows up in related-product carousels.
- **Bot walls served as 2xx** (SiteGround's `sgcaptcha`, Cloudflare and Imperva challenges, a bare 202) count as "needs a human". **cnqsmotor.com now does this to the checker** (HTTP 202 → captcha), so its 19 buy links and its vendor page show as "needs a human" and not live. In Phase 3, curl got 200s. The checker doesn't spoof a browser User-Agent.
- **`--apply` edits YAML in place** by the `status` value's source range, so comments and folded text stay byte-for-byte the same, then reruns `verify:list`. (Re-serialising with the `yaml` package unwrapped folded strings.)
- **Workflow-made PRs don't trigger CI** (pushes with `GITHUB_TOKEN` start no workflows). `ci.yml` gained `workflow_dispatch`, and the link-check workflow runs `gh workflow run ci.yml --ref link-checker/dead-links`; the check run attaches to the PR's head commit. The dead-links branch is force-pushed and the PR reused, so re-runs never duplicate it. The rolling issue is found by label + an HTML marker; any duplicates are closed.
- **PR mode** (`--changed-since origin/<base>`) checks only URLs that appear in changed content files (and `src/data/specs.ts` / `community.ts`) but weren't in the base versions. It writes to the job summary, exits 1 only on dead links, and says "skipped" when no content changed. CI checks out full history on PRs for this.
- **Help Wanted** (`/contribute/help-wanted`, data in `src/lib/help-wanted.ts`): a summary row of counts, buy links grouped by vendor (most first), unknown values (vendor URLs that are `TODO`, guide `time_minutes: TODO`, and every "TODO…" sentence in guide and troubleshooting text and checks, except notes about the site's own roadmap such as "(Phase 6)"), the Specs page's `gaps`, and guides with no `verified_by`. Prices and URLs show as reasons on buy rows and aren't listed twice. Each item opens the web form prefilled; edit links show once GitHub contributions are open.
- **"I checked this"** opens the broken-link form with the new first option **"It works: I checked it"** (`LINK_CHECKED`), the vendor, the URL and a summary. The question now reads "What did you find?", and the price field reads "Price you saw, or a working link". The form also prefills `problem` and `summary` from the URL. Issue forms were regenerated. The editor treats such a report as a verification (CONTRIBUTING → Reviewing).
- **Changelog page** (`/contribute/changelog`, `src/lib/changelog.ts`): date, PR number (linked once GitHub is open), title, known labels, "thanks to", pages changed (content files map to their pages by file name, plus Specs, Community, Help wanted and plain `.astro` routes; up to 8, then "+N more"), a count of other files ("site code"), and closed issues. Backfilled with the only merged PR so far (#1). Phases 1–3 were pushed straight to `main`.
- **New label `link-check`** in `LABELS` (`npm run labels:sync`; the workflow also creates it if missing).
- **Template tweaks (no restyle):** home gets a fourth section, "04 Help wanted" (one row with counts). Contribute opens with Help wanted and Changelog rows, and "04 The link checker" now explains the outcomes. PageMeta shows "improved by: … · changelog" under last verified. Help Wanted buy rows use the row inset without hover (each has several actions); its count summary is a row list on phones and four columns on desktop.
- **Validation:** `test:validation` now also proves an email address in `contributors` is rejected. `test:links` (16 tests, no network) covers classification, bot-blocking hosts and the staleness rule, and runs in `npm run ci`.
